# Frozen stellar transformation reference

`astropy.json`: 12 selected HYG stars × four synthetic sites (Istanbul, Sydney, zero coordinates, 80° N / 2500 m) × three UTC instants (2000, 2026, 2035), 144 numeric samples. Input J2000 catalogue values are shared facts; the transformation is independent Astropy/ERFA `apply_space_motion` + airless `AltAz`, compared with the actual frontend adapter using Astronomy Engine rotations/Earth state. This tests the transformation, not independent truth of HYG itself or every bundled star.

Generate only explicitly with `.local/science-venv/Scripts/python.exe scripts/science/refresh_star_references.py`. The isolated environment is created with Python 3.12 and `scripts/science/requirements-reference.lock.txt` (Astropy 8.0.2). It is a validation tool, not a runtime Python service. IERS auto-download is disabled; bundled IERS/leap tables are frozen. All six distinct future IERS/ERFA warning types are retained in the JSON and published report, including the 2035 reference limitations.

The JSON records catalogue SHA-256, generation time, Astropy/IERS versions, frame/units, assumptions and 1 arcminute trial target. Test/probe never regenerates it or calls a remote service. Compare using `npm test` in the Web project, or `node --experimental-strip-types tools/science-js/star-probe.mjs` from the repo root. [Public report](../../../docs/science/star-reference-report.json), [method and limitations](../../../docs/harita-ve-katalog-denemesi.md). Astropy/ERFA references are numeric validation facts; no third-party images or text catalogues are copied here.
