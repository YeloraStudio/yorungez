# Native accounts and connected exploration — K-054

Owner direction, **5 November 2026**. This extends FR-01/02/03/04/09/10/11 and the existing sky-first mobile contract. The delivery below is implemented; verification and remaining native/release acceptance are recorded separately.

## Required delivery

1. Sidebar sign-in/create-account or signed-in full name, profile and notebook. Reuse the existing .NET Bearer, verification, refresh, language and notebook contracts. Registration collects first name, last name, email and password; confirmation/reset email keeps its working Web fallback. No real recipients are contacted by developer tests.
2. Access token stays in memory; only the rotating refresh credential goes in platform-secure storage. Single-flight refresh, account-generation guards, logout/revocation and storage failures must not leak one account's data into another. Personal inventory/drafts remain server-owned/in-memory, never a durable offline database or write queue.
3. Apply the same account `preferredLanguage` as Web after sign-in and on foreground refresh; default English without an explicit preference. Save authenticated language through the API before applying success. Non-personal music/layer preferences use a bounded typed account API; no observer coordinates, sensor samples or alignment are account preferences.
4. Once privacy onboarding is complete, prioritize granted device location and native pose automatically. A recent, accurate OS location may provide a fast provisional context while a fresh fix is requested. Preserve explicit manual fallback, permission denial, revocation, stale-data/reference and WMM validity gates. Account/network latency must not block general offline sky calculations.
5. Make source/image/licence links actionable through an external HTTPS browser, with safe URL validation and visible failure. From any object detail, focus that same ID in the live sky; preserve the observer, pause sensor control for the explicit focus and keep a clear return-to-phone action. Deferred focus waits for a calculated frame, not a fake catalogue direction. Expired ISS data remains unavailable.
6. Display **Yorungez** in mobile UI/native app labels. Keep package/application/channel/data IDs and original logo files unchanged. Add a discreet `yorungez.com` link to the sidebar. Web store buttons remain a release follow-up until real store URLs exist; do not invent store availability.

## Implemented contract and verification

- Existing Bearer register/login/refresh/profile/language/confirmation/reset requests are wired into native EN/TR account screens and the sidebar. Notes, favourites, observations and saved places are read from the same server notebook; native note create/edit and favourite creation use its revision-aware write contract. Full observation/place editing, Tonight/Calendar/glossary and store links remain later parity work.
- `GET/POST /api/v1/auth/exploration-preferences` stores music and the nine allowed layer keys in `identity.ExplorationPreferences`. It is authenticated/no-store, supports the existing expected-account header and requires an expected revision. Default revision zero is a virtual default, not a row written on every login. Concurrent insertion/update is rejected with a localized 409; name/language updates cannot overwrite the separate preference row. Migration `AccountExplorationPreferences` adds only this account-owned table.
- Access tokens are memory-only. A host-scoped secure-store item holds only refresh credential/expiry. Android backup/transfer rules exclude preference credentials; iOS uses an unsynchronized, unlocked-this-device Keychain item and checked-in non-secret entitlements. Refresh is single-flight and 401 replay is bounded; uncertain personal writes are never replayed. Logout hides private views immediately, clears storage and attempts family revocation even if deletion fails. Storage failure is visible and never falls back to plain preferences; retry cannot restore a credential awaiting deletion.
- Account language applies after server success and refreshes on foreground return. Failed selections reset the picker to the confirmed language. Non-personal anonymous language/mute remains local. Music/layer changes are serialized at the UI and conflict/error remains visible rather than overwriting another device.
- After completed privacy onboarding, permission is checked without prompting. An OS-cached fix is used only within 60 seconds and 200 m accuracy; a fresh foreground fix follows, refreshes periodically and resumes with the app. Manual choice wins over a late fix. Latitude/model/freshness gates remain. An explicit target focus pauses sensors/camera, keeps the current observer, survives detail navigation and updates the calculated target at live UTC; GPS refresh does not silently cancel that focus. General catalogue/sky work does not wait for account HTTP.
- Source/image/licence and Wikipedia-search links are actionable HTTPS intents with visible failure; no token or observer coordinates are put into those links. Sidebar website links carry the selected public language only. Mobile text/native labels now display Yorungez; identifiers and supplied logo masters remain unchanged.

Tests cover transport headers/safe failures, rotation/concurrent 401s, revoked/stale sessions, storage write/delete failure, logout/account switching, server-first language, wrong-owner reads, no uncertain-write replay, EN/TR registration at narrow/landscape sizes, notebook navigation, safe source intents, cached/fresh location gates and retaining the same sky/observer when returning from detail focus.
